# FAA density, 1,200-second outbound CG comparison

Requested comparison: CG + rounding, CG + LNS, and CG + IP after every round.
Started September 8 and finished September 9, 2026. All work remains in
`/private/tmp/congestion-colgen-lns-20260905`, branch `codex/colgen-lns-main`.
No production code changed for this experiment. The existing per-round-IP feature
and the eager-row benchmark wrapper from the previous experiment were reused.

## Protocol

- Scenario: `density_faa_wing_zipline`, seed 0, 1,200-second demand-generation window.
- Generate the original 3,074 paired legs, then retain the 1,537 outbound flights,
  preserving IDs, coordinates, departure clocks and 182 static terminals. This
  continues the outbound-only setup used in the preceding comparisons.
- Three fresh sequential processes, identical source/configuration/requests.
- Four pricing workers and four Gurobi threads; warmed Numba before measurement.
- At most 30 CG rounds, 0.01% LP cost-gap target, zero native IP gap target.
- Each arm reserves 660 seconds for final IP setup/search; final native search cap
  is 600 seconds. Overall cap is 14,460 seconds per simulation.
- Rounding and LNS are the primal policies during CG; all arms retain final IP.
  LNS uses 100-flight neighborhoods, 16 trials, and a 0.5-second joint repair cap.
- The IP arm replaces both heuristics with a full-pool IP after every completed
  pricing sweep, preparing all bindable capacity rows before its 30-second native
  search budget. This eager preparation is a recorded benchmark wrapper, not a
  change to the default production per-round-IP mode.

Exact command, source archive, input files, logs and traces are under
`analysis/colgen_faa_1200s_20260908/`; its README gives reproduction instructions.

## Interpretation

- LNS reduces completed-run wall time by 6.7925% versus rounding with identical
  final cost. Column and path files match byte for byte: both controls generated
  precisely the same alternatives. Their final trajectory hashes differ, despite
  identical aggregate cost, ground delay and air detour; do not claim identical
  final schedules.
- LNS saves 229.49 seconds in heuristic work plus canonicalization, explaining
  most of the 327.86-second overall saving. Pricing differs by 87.28 seconds on
  identical work; this is one timing sample, not demonstrated algorithmic pricing
  acceleration. Final IP is slightly slower with LNS's better seed (34.30 vs
  30.11 seconds). LNS published 20 distinct retained solutions over 30 calls.
- IP after every round reaches cost 157,595.032482 in round 8, available after
  32.08 minutes. This beats the controls' eventual 157,656.175752 cost, reached
  after 74.87 minutes by LNS and 80.33 minutes by rounding (capacity-checked solve
  output, before final filing overhead). Time to that quality is 2.3338 times
  faster than LNS. This measures outputs available under these configured
  policies; an early-stopped control with its own earlier final IP was not tested.
- Completing the full IP policy takes 29.82% longer than LNS and 21.01% longer
  than rounding for 0.7935% lower final cost. Total ground delay falls by 1,264
  seconds (47.8788%). Air detour increases by 129.842 metres, corresponding to
  about 12.984 cost units; do not infer ground delay from total cost alone.
- IP rounds 1–10 hit their 30-second search caps. Rounds 11–30 proved pool
  optimality. Every returned incumbent covered all 1,537 flights. The best final
  cost was first reached in round 24 at 77.80 minutes; the remaining 19.54 minutes
  improved the bound but did not reduce schedule cost.
- The IP policy changes later LP duals and pricing columns. It shares 34,013
  exact timed columns with either control, with 21,816 only in IP and 10,717 only
  in the controls. This is a policy comparison, not a comparison on fixed pools.
- Pricing remains dominant. Each arm had one exact label-pool restart on flight
  1600, and no compiled-kernel fallback. Lower seconds per added column for IP
  includes changed search work and more added columns; it does not isolate a
  faster pricing kernel.
- The practical benefit of per-round IP here is obtaining good schedules early.
  Running all 30 rounds adds substantial time for small late improvements. A
  follow-up could compare an earlier final IP or less frequent IP calls, but those
  alternatives have not been measured in this experiment.

## Artifacts and validation

- `analysis/colgen_faa_1200s_20260908/summary/report.md`: full comparison and per-round IP table.
- `analysis/colgen_faa_1200s_20260908/summary/comparison.png`: cost availability and runtime components.
- `analysis/colgen_faa_1200s_20260908/summary/audit.json`: machine-readable audited results.
- `analysis/summarize_colgen_policies.py`: reusable auditor/reporter for this three-arm harness.

The audit verifies exact normalized inputs, identical production-source hashes,
archived source/harness/tracer/patch hashes, coverage, IP selection costs/budgets,
monotonic incumbents and valid bounds. It recomputes congestion cost from all filed
trajectory metrics and checks agreement with the solver objective. The simulator
physically conflict-verified every final flight. Ruff and `git diff --check` pass.
No new production tests were needed: production code was unchanged, and the new
analysis script was exercised on archived data and the completed three-arm data.
