## Context

Add a planner named `colgen` that optimizes the **whole flight schedule at once** (vs. today's FCFS per-flight A*/MILP), implementing the deterministic column-generation method of Balakrishnan & Chandran, *Optimal Large-Scale Air Traffic Flow Management*, **Section 4 only** (no stochastic part). It plans over the same hex lattice A* uses, on a space-time network whose capacity rows are derived from the ledger's actual reservation geometry so that **any row-feasible integer solution files against the ledger with 0 denials** (priority 1). The column-generation loop follows the paper's algorithm and must be fast (priority 2). Shortcutting is a post-pass over the final solution in planned-departure order (priority 3). Rolling horizon is a follow-up (design leaves the seam open).

Paper: `.context/attachments/t1EoIQ/BalakrishnanChandran_ATFM.pdf` (Balakrishnan & Chandran, 34 pp). This plan is committed into the repo in PR A Phase 1 (`context/colgen_plan.md`) so future agents can pick it up mid-stream.

**User decisions (2026-07-31, all confirmed):**

(6)**: sectors are hex sectors (cap 1) + terminal sectors (cap = pads) ONLY; R_S(s,t) = routes passing through s at steps {t−1..t+2} (equivalently: a visit at step v joins rows t ∈ {v−2..v+1}). The literal 30-arc/swap-sector/feeder-grouping encoding is superseded (documented in §3 for rationale).
2. **v1 levers = ground hold + route on a SINGLE flight level** (no air holds, no mid-route level changes; multi-level level-choice is the first extension, §9).
3. **Acceptance bar = correctness + optimality (paper's gap machinery) + decent speed on `colgen_test`**; density-scale speedups deferred to the performance PR.
4. **Objective = minimize TOTAL DELAY with every flight weighted equally** (ρ_r = M − delay_s(r)); scenarios default to all-flights-equal. Per-flight cost weights are a future hook (a per-flight multiplier on the delay term), not v1. `intent.cost` is still *reported* in the repo currency via `trajectory_cost` for cross-planner comparability, but the optimizer's objective is delay-seconds.
5. **Planner class name: `ColumnGenerationPlanner`** (registry string stays `"colgen"`).
6. **Delivery structure: ONE PR with three reviewed phases** (network/rows → solver → integration+scenario), then a shortcut PR, then a performance PR. **After every phase: run the full test suite, then PAUSE for user review; commit only after approval.**
7. Returns-as-tails (mission columns), rolling horizon, heterogeneous speeds: explicitly scheduled in the §9 backlog, not v1.

9. **(2026-08-01) Solver: Gurobi is the PRIMARY LP/IP backend** — the user will install it (gurobipy + license) before execution; **HiGHS (scipy) is the always-available fallback** and the CI path. Auto-detect via guarded `import gurobipy`; `ColGenParams.solver ∈ {"auto","gurobi","highs"}`. gurobipy is NEVER a hard dependency of the repo (license-bound; not added to default deps). Gurobi restores the paper's warm-start behavior: persistent model across RMP iterations (incremental columns/rows, basis reuse) and MIP starts for the final IP; the HiGHS path re-solves cold (acceptable at colgen_test scale — noted per plan-critic round 3 MOD-2, scipy.optimize.milp has no warm-start parameter).
10. **(2026-08-01, Phase-1 implementation clarification) Timing bounds preserve the whole budget:** `FlightGraph.max_step` includes the worst takeoff climb and origin-lane traverse in addition to latest legal departure + route/slack; those mandatory clocks do not consume the ground-delay or routing allowance.
11. **Endpoint spatial reach generalizes the default `+60 m`:** use `r_cyl + max(corridor_width_m, effective_hover_radius_m) + circumradius`, identical at defaults and covering custom larger endpoint cylinders.
12. **Static walls get an exact endpoint guard:** graph construction rejects any customer or differently tagged terminal endpoint cylinder overlapping a permanent foreign terminal cylinder. Static walls are exclusions, not master rows, so snapped-cell exclusion alone is insufficient.
13. **Visit-only rows fail closed on unsupported corridor geometry:** graph construction checks that conflicting lattice hops always share an endpoint cell and rejects configurations that violate the invariant. Deriving hex size/pitch from corridor geometry is tracked in GitHub issue #72.
14. **(2026-08-02, Phase-1 review correction) The integer lattice clock is authoritative at translation:** every logical lateral hop occupies exactly one `dt_s`, even when `build_reservation_from_corners` subdivides that hop. Sub-box times must partition the exact logical-hop interval, and the destination dwell starts at `corridor_t0 + (len(cell_path) - 1) * dt_s` exactly; distance-derived floating-point drift may not extend a reservation across a row boundary.
15. **Static-wall safety is certified against exact translated volumes, not inferred from `terminal_cells`:** `terminal_cells` remains a routing prune only. `column_claims` checks every candidate against every permanent terminal reservation with the ledger's `volumes_conflict` predicate and the builder's actual tags before the candidate can enter the RMP/normal translation path. This rejects walls with an empty cell projection and the distinct-hub one-box case in which one box overlaps both endpoint columns but can carry only one `terminal_id`.
16. **Every column contains at least one lateral hop:** `len(Column.cell_path) >= 2` is a construction, claims, pricing, and translation invariant. Equal endpoint-center cells and terminal-lane/customer combinations that collapse to one cell have no legal v1 column; two disconnected endpoint cylinders are never a trajectory.
17. **`max_detour_factor` is a hard column-universe constraint with one canonical verdict:** `column_to_intent` computes the translated filed-centerline ratio with the same `straight_ref > 1e-9 and flown / straight_ref > cfg.max_detour_factor` rule as `astar.py`; `column_claims` requires that exact translation to be accepted instead of maintaining an independent logical-center calculation. Phase-2 pricing must pass candidates through `column_claims` before they enter the RMP.
18. **Terminal rows use exact half-open dwell periods, independently of customer-cylinder padding:** a terminal interval `[t0, t1)` claims exactly periods `k` satisfying `k*dt_s < t1 and (k+1)*dt_s > t0`. `endpoint_claim_steps` remains the outward conflict window only for untagged customer cylinders; it must never be reused for pad rows.
19. **`FlightGraph.cell_to_index` is genuinely immutable and picklable:** freezing the dataclass is not sufficient if it exposes a mutable `dict`. The public value is an immutable `Mapping` with no mutation API, survives a pickle round trip, and retains stable dense indices.
20. **The Phase-1 gate includes a regression for every 2026-08-02 finding:** exact-hop clock/row coverage, dual endpoint walls, empty terminal-cell projections, one-cell paths, detour-factor rejection, exact terminal periods, and index immutability+pickle are all pinned before the full-suite review pause.
21. **Global wall pruning must preserve context-dependent safe tags:** `network.py::_forbidden_static_hops` reproduces the builder's scalar subdivision and per-subbox geometric tags. Because a directed arc can be first, last, or internal in a wide loop, it is globally forbidden only when every possible fixed-lane tag variant conflicts. Ambiguous arcs remain in pricing and are decided by `column_claims` against the translated full column.
22. **Claims and filing share one detour-budget verdict:** `network.py::column_claims` calls `translate.py::column_to_intent` even in wall-free graphs and accepts claims only for an accepted translation. It does not independently sum logical centers; a one-ulp difference from resampled filed geometry may not create a row-feasible column that is denied during translation.
23. **Phase-1 immutability includes backing state and request geometry:** `_ImmutableCellIndex` rejects attribute reassignment and repeat `__init__`, not only item assignment. `build_flight_graph` stores an immutable `FlightRequest` subclass snapshot: endpoint arrays are views over immutable byte buffers (so `setflags(write=True)` also fails) and every request attribute is locked, including terminal metadata; both locks survive pickle. Later demand or snapshot mutation cannot desynchronize cells/lanes/terminal rows from canonical translation.
24. **Every network coordinate/clock field is integral and direct translation enforces both budgets:** `Column` normalizes integer-like values with `operator.index` (including NumPy integers) and rejects fractional steps, levels, lane indices, and cell coordinates without truncation. `column_to_corners` defensively repeats the clock checks; `column_to_intent` returns `BUDGET_EXCEEDED` when a direct caller exceeds the same quantized ground-delay bound as the graph.
25. **Both terminal cylinders use the authoritative integer clock:** translation re-times the origin cylinder to `departure_step * dt_s` and the destination cylinder to the exact arrival step, recomputing each end with `hover_time_s + column_dwell_s` in ledger operation order. It never retains `t_departure + (departure_step*dt_s - t_departure)` cancellation drift that would add an unclaimed terminal period.
26. **Hub endpoints require fixed exit lanes in colgen v1:** both `build_flight_graph` and direct `column_to_corners`/`column_to_intent` raise a clear `NotImplementedError` for a terminal endpoint when `fixed_exit_lanes=False`; customer↔customer graphs remain supported. The legacy center/fold endpoint semantics require a separate extension and are not silently represented by fixed-lane claims. The same public-boundary rule applies to the existing `terminal_airspace_always_active=True` hub requirement.
27. **(2026-08-02, Phase-2 implementation correction) Gap tests use the transformed delay objective, not M-dominated revenue:** with `N` flights, the restricted cost upper bound is `N*M - RMP_obj`, the pricing-derived cost lower bound is `N*M - revenue_UB`, and an integer incumbent's cost is `N*M - incumbent_revenue` (therefore charging `M` for every omitted flight). Relative LP/heuristic gaps are computed from those costs. Dividing a revenue difference by `N*M` can satisfy the nominal 0.01%/0.1% thresholds while tens of avoidable delay-seconds remain, prematurely stopping pricing and skipping the final IP.
28. **(2026-08-02, Phase-2 implementation correction) `detour_slack_hops` bounds the spatial ellipse, not route length:** non-seed pricing may use the remaining graph clock for W-separated wide loops; only the dual-free seed search uses the shortest+slack hop bound. A priced regression revisits its origin exactly at W and has more hops than `shortest_hops + detour_slack_hops`, while all tighter revisits remain forbidden.
29. **(2026-08-02, Phase-2 fixture correction) The 32 s head-on theorem is a path-row/master test:** a full axial customer↔customer overlap necessarily traverses the other flight's inner destination, whose canonical dwell-cylinder claims outlive the eight-step separation. The former full-solver fixture was geometrically inconsistent with its expected value; the restricted-master test pins the intended five-cell row arithmetic, and a disjoint-endpoint crossing fixture pins full-solver budget denial/repair behavior.
30. **(2026-08-02, Phase-2 pricing correction) dominance retains one predecessor even when `time_buffer_s=0`:** W=2 needs no predecessor for the revisit ban, but sink endpoint de-duplication can distinguish two labels that reach the same cell through different predecessor visits. The DP state therefore keeps `max(2, hi_off - lo_off)` recent cells while the revisit check still consults exactly `hi_off - lo_off`; only active origin-endpoint rows are carried for historical de-duplication, preserving visit/visit dominance under W-separation.
31. **(2026-08-02, Phase-2 repair correction) feasibility is independent of reduced-cost sign and seed availability:** repair requests the best feasible column even when a deliberately small `M` makes its reduced cost non-positive. A disconnected/static-blocked graph may have no seed and is an optimizer-verdict denial for that flight, not a batch-wide exception; pricing still runs the full DAG because a path-dependent wall check can invalidate the deterministic seed without disconnecting every route.
32. **(2026-08-02, Phase-2 MIP-gap correction) native backend gaps are converted out of Big-M revenue units:** the configured `ip_gap` is a transformed delay/cancellation tolerance. Backend relative-revenue tolerance is conservatively `ip_gap / max(1, N*M)`, and both backends return their incumbent bound. Solver stats report the revenue bound plus transformed IP cost bounds/gap, so a time-limit incumbent is auditable and `N*M` cannot hide seconds of avoidable delay.
33. **(2026-08-02, Phase-2 hub-pricing correction) elapsed lattice time is not itself a valid detour lower bound:** for fixed terminal lanes, an additional lattice hop can replace destination fold distance without increasing canonical flown/reference delay. Prefix pruning uses only irrevocable ground delay and already-unioned row duals (plus a conservative allowance for negative tolerance duals); exact translated detour is evaluated at the sink. A hub↔hub regression pins the formerly pruned optimum.

**Glossary:** **row** = one capacity constraint instance, keyed `("cell", q, r, L, t)` cap 1 or `("term", tid, t)` cap pads — paper eq. (6) with our membership rule. **claim** = a row a column is a member of; a column's claim set is a frozenset of row keys. **footprint / reservation presence** = the set of (hex, period) pairs a flight's ledger volumes overlap; membership rule for rows. **visit** = a flight's center-crossing of a hex at step v; its footprint in that hex is `visit_rows(v)` = {v−2..v+1} at defaults. **offsets (lo, hi)** = the measured footprint window relative to a visit (−2, +1 at defaults); W = hi − lo + 1 = 4. **W-separated** = a path that never revisits a cell within W steps (the column universe). **fold leg** = the sub-hop distance `lane.dist − exit_radius` a hub flight flies beyond the metrics fold (priced on takeoff/arrival arcs); **hex-snap leg** = customer analog `‖P − hex_center(cell(P))‖`. **column** = one flight's candidate trajectory (paper's x_r variable) with its delay_s and claims. **RMP** = restricted master problem (LP over current columns, materialized rows only). **pricing** = per-flight longest-path DP that proposes new columns from duals. **repair pass** = post-IP sequential pricing with saturated rows forbidden, guaranteeing every flight a column or an optimizer-verdict denial. **covering theorem** = conflict per `volumes_conflict` ⇒ shared cap-1 row (the 0-denial guarantee). **always-active walls** = permanent per-hub tagged cylinders (`register_static_terminal`).

## 1. The paper's method (Section 4), reduced to what we implement

**Master problem (IMP, paper eq. 4–8).** Variable x_r ∈ {0,1} per *trajectory* (a timed path). maximize Σ ρ_r x_r subject to:
- Σ_{r ∈ R(f)} x_r ≤ 1 per flight (≤1 keeps the RMP always feasible; with a large benefit constant M in ρ_r = M − cost_r, "cancellation" is never chosen when a trajectory exists),
- capacity rows: Σ_{r intersecting row} x_r ≤ B_row. Paper: sector rows count aircraft ON the sector's arcs during period t (an aircraft entering an arc at t1 and leaving at t2 occupies periods t1..t2−1); node-throughput rows count entries. We use only "sector-style" rows (see §3).

**Column generation loop (paper Fig. 8, §4.2):**
1. RMP starts with seed columns; duals 0.
2. Pricing per flight (embarrassingly parallel): longest path in a flight-specific space-time DAG; arc weight = benefit at destination arcs − operating cost Ω(a, τ) − Σ duals of rows the arc intersects. Reduced cost = path weight − π_f; add column if > 0.
3. Re-solve RMP LP. Paper: primal simplex + PreDual (rows ≫ cols, ~100 nz/col); we use HiGHS via scipy.
4. **Upper bound** each iteration: UB = RMP objective + Σ_f max(0, best reduced cost of f). Terminate at LP gap ≤ 0.01%, heuristic-IP gap ≤ 0.1%, or iteration/time cap. Paper needs 12–22 iterations.
5. **Rounding heuristic** after each LP: values truncated to [ε, 1−ε]; round up w.p. value unless a row would be violated; then greedy pass over remaining columns by objective; repeat a few times, keep best → feasible integer solution + IP warm start (in our implementation the warm start reaches the solver only on the Gurobi path; HiGHS uses it as incumbent/early-exit — §5 Phase 2).
6. Final: IP over the RMP's columns (paper: solves at root; gap ≤ ~0.1%).

**Costs** (paper §6.1.4: en-route 1.0 / taxi 0.5 / gate-hold 0.1 per period): **v1 objective = minimize total delay-seconds, all flights equal** (user decision 4). The **normative** definition of a column's objective term `delay_s` is §3's arc-priced form (hops·dt + fold legs + ground·dt − ref_time, which equals `metrics.total_delay_s` exactly); it coincides with the intuitive `ground_hold + detour time` up to a per-flight constant, so pricing/argmin are unaffected by the constant. ρ_r = M − delay_s(r). Per-flight weights later = per-flight multiplier on delay_s (paper's Ω supports arbitrary flight-specific linear costs). `intent.cost` is still *reported* via `trajectory_cost(intent, cfg)` (repo currency 1:3:3:4, `config.py:64-67`) so runs remain comparable with A*/MILP.

## 2. Verified ledger geometry (measured, not assumed)

From explorer reports + direct enumeration with the repo's `volumes_conflict` (run in-plan; re-derived in code + pinned by tests):

- Hop = 120 m = 1 step (`dt_s=4`, speed 30 → pitch = `corridor_segment_len_m` = 120; `hexgrid.circumradius`). Corridor box per hop: extents (180, 60, 30) — ±30 m longitudinal extension, ±30 lateral, ±15 vertical; window `[t0−4, t1+4)` = 12 s (`volumes.corridor_segment_volume`, volumes.py:60).
- **Conflict offsets (steps), same flight level** — template pairs, `volumes_conflict`:
  - same directed edge: conflict iff |Δ| ≤ 2; swap (opposite dirs, same edge): |Δ| ≤ 2;
  - trailing same lane (adjacent box pairs): |Δ| ≤ 3; crossing same cell via different edges (60° and 120°): |Δ| ≤ 3; hover-box vs transit: |Δ| ≤ 2;
  - **max over all same-cell classes = 3** → min legal separation at a shared (cell, level) = 4 steps (16 s) ⇒ **window width W = 4**.
  - two lattice edges that share **no** cell: **never conflict** (min gap 103.9 − 60 = 43.9 m). Lattice edges only meet at cell centers (triangular dual) — no crossings. A hop box ⊆ union of its two cells' hexes (30 m overhang + 30 m lateral ≤ 60 m inradius).
  - adjacent flight levels never conflict (`SimConfig.__post_init__` enforces level gap > `corridor_height_m`).
  - vertical rung box (30→70 at cell B): conflicts level-30 transit through B at |Δ| ≤ 3; never conflicts transit through adjacent cell or through level 110.
  - customer hover cylinder (radius 60, z 0–125, window `[t0, t0 + 30 + climb)` ≈ 41.7 s): conflicts hops on edges incident to nearby cells throughout its window (+box buffer); never reaches edges of cells ≥ 2 rings away.
- Terminal machinery: own-hub tagged cylinders are mutually exempt (`conflict.volumes_conflict` tag+cylinder rule); **box↔box same-tag still conflicts** (two same-lane departures contend). Pad capacity is enforced ONLY by `TerminalCapacity.admits` (count of same-hub dwell intervals overlapping `[t0, t0 + hover_time_s + column_dwell_s)` < pads) — the ledger is blind to it. Always-active walls: per-hub tagged cylinder radius `terminal_radius`, `[0, 1e12)`; A*'s discrete walls block `hexgrid.terminal_cells` (covered ∪ boundary ring) at all levels; exit lanes = the boundary ring (`terminal_lanes`).
- A* takeoff quantization (colgen mirrors it exactly): ground hold at origin (unreserved, `cost_ground_delay_per_s·dt` per step) → takeoff at step s → corridor begins at the **lane hex centre** at `ts = s + takeoff_steps[L] + lane.steps`; committed volumes = `[tagged origin hover(t_takeoff, climb_time_s=column_dwell_s), corridor boxes (first/last force-tagged), dest hover]` — all produced by `build_reservation_from_corners(corners, …, corridor_t0=ts·dt)`.

The outbound's landing cylinder and the return's takeoff cylinder at the same customer point are cross-constrained automatically by the endpoint-claim rows — no tail logic. |

### Row (capacity-constraint) catalogue — the entire constraint system, mapped to paper eq. (4)–(8)

**(4) objective, (5) ≤1-per-tail, (8) binarity: unchanged.** **(7) node envelopes: unused** (J(n,t)=∅) — deliberately, not by omission (user question, answered): the paper's node rows encode minutes-in-trail spacing at fixes and runway arrival/departure envelopes. Our cap-1 hex rows with reservation-presence membership already impose a 16-s minutes-in-trail at *every* cell simultaneously, and are strictly stronger than a throughput row (they also bind crossing and opposing flows through the same point, which entry-rate counting does not). The runway-envelope analog is the pad: departures AND arrivals consume the same Terminal(term, t) rows over their dwell windows — exactly `TerminalCapacity.admits`, and the repo has no arrival/departure rate tradeoff to encode beyond pad occupancy. If a rate envelope is ever wanted (e.g. per-lane throughput policy), eq.-(7) rows are just another keyed row family in `RowIndex` with σ-coefficients — the machinery is envelope-ready, unused. **(6) is the only constraint touched, and only through its membership set** R_S(s,t): sectors are the user's hex sectors (B=1) + one sector per terminal (B=pads); membership is **reservation presence**, not physical presence — `r ∈ R_S(H, t)` iff r's ledger reservation (boxes incl. ±4 s buffer and ±30 m extensions, cylinders) overlaps hex H during period t. Arcs/transit times/ST-network rules are the paper's, untouched (a hop still takes 1 period); only the (6)-row coefficients widen. The paper's descriptive "a trajectory intersects at most one sector constraint at a time" is dropped — nothing in the formulation, duality, bounds, or Lemma 4.2 relies on it. Membership of a column is precomputed when the column is generated ("claims"):

1. **Hex rows (H, L, t), cap 1** — a traversal with center-visit at step v belongs to rows t ∈ {v−2, v−1, v, v+1} (its two corridor boxes hold H for exactly those 4 periods; derived W=4, re-derived from `volumes_conflict` templates at build). Covers same-edge headway, swaps, crossings, trailing — all measured conflict classes.
2. **Endpoint claims** — a takeoff/landing cylinder at point P (radius r, window [T0,T1)) claims (c, L, t) for **every level L**, every cell c whose hex intersects disk(P, r + 60 m), every period t whose transit-window can overlap [T0, T1) (exact step algebra derived in code). Coverage argument: cyl↔hop — a hop box overlapping the cylinder lies in its two cells, each of whose hexes then intersects disk(P, r+60), and the hop's own visit marks hit those cells' rows in the overlapping periods; cyl↔cyl — two cylinders overlap ⇒ |P1P2| < r1+r2 ⇒ cell(P2) ∈ claims(P1) (hex(P2) ∋ P2 ∈ disk(P1, r1+r2 ≤ r1+60)) and cell(P2) ∈ claims(P2) trivially → shared row.
3. **Terminal rows (term, t), cap = pads** — every hub departure/arrival claims exactly the periods touched by its half-open dwell interval `[t_takeoff_or_arrive, + hover_time_s + column_dwell_s(z))`: period `k` is included iff `k*dt < t1 && (k+1)*dt > t0`. This is a separate helper/semantic from `endpoint_claim_steps`: customer cylinders need padded cell-row claims against buffered transit, whereas pad occupancy mirrors `TerminalCapacity.admits` and must not inherit that padding.
4. **Statics (not rows — pruning plus exact column certification):** foreign hubs' `terminal_cells` are removed from every other flight's network as an A*-parity optimization, but this discrete projection is never treated as a proof of wall safety. Before claims are returned and a candidate may enter the RMP, `column_claims` checks its exact translated `Volume4D`s and tags against every `permanent_terminal_reservation` with `conflict.volumes_conflict`. A differently tagged conflict invalidates the column. This catches small/off-grid walls whose `terminal_cells` projection is empty and a one-box route touching both distinct endpoint walls, for which `build_reservation_from_corners` can preserve only the origin tag (`volumes.py:397-400`).

**Sufficiency theorem (the 0-denial guarantee), 3-line proof:** if two selected columns were denied at filing, two of their volumes overlap at some point p at instant τ; p lies in some hex H (or terminal disk) and τ in some period t; both reservations then overlap H during t, so both columns are members of the cap-1 row (H, t) — contradiction with row-feasibility. Requires that (a) claim computation rounds customer geometry/time **outward** (never misses a (hex, period) the reservation touches), (b) translation preserves each discrete hop's exact `dt` clock, and (c) every column has independently passed exact permanent-wall certification. These are pinned by the exhaustive covering test over all template arc-pairs × relative cell offsets (≤ 3 rings) × step offsets (± 8) × seeded random endpoint offsets, asserting `volumes_conflict(v1,v2) ⇒ shared row`, plus candidate-vs-static-wall filing tests. `terminal_cells` is pruning only and is not an assumption in the proof.

**Column universe (routing restriction, paper §3.2.1):** columns are paths that never revisit a cell within W steps ("W-separated"). Reason: dual attribution in pricing is per cell-visit (entering H at v adds the 4 rows (H, v−2..v+1) — a function of v alone, independent of entry/exit edges); a revisit within ≤3 steps would overlap row-sets and double-count duals, corrupting pricing exactness and the UB. Wide loops (return after ≥ 4 steps) stay in the universe and are exactly priced — en-route waiting-by-looping survives; only ≤3-step micro-zigzags are excluded — under the delay objective they are *tied with* (not dominated by) ground-holding, so excluding them is value-preserving because ground hold is unbounded (3600 s) and achieves the same delays. All bounds/optimality claims are w.r.t. this universe, exactly as the paper's claims are scoped to its chosen flight networks A_F(f). Guard: every candidate column's reduced cost is recomputed from its de-duplicated claim set before adding (cheap exactness check).

**Generality of W (user question, answered):** W is *measured*, never assumed — it is the number of periods a traversal's reservation overlaps its hex, derived at build time from `volumes_conflict` templates. The sufficiency proof uses only "membership rounds outward" + "hexes tile space", so the machinery is valid verbatim for W = 3, 2, or 1 under tighter configs (e.g. `time_buffer_s = 0` ⇒ W = 2). W = 1 is structurally unreachable with the *current* builder: the ±30 m longitudinal extensions put both the in-box and the out-box inside the hex on consecutive 12-s windows, forcing ≥ 2 periods — a property of `corridor_segment_volume`, not of the formulation.

**Row-space arithmetic (why lazy rows are mandatory, user question):** full row space = cells × levels × periods. `colgen_test` (8×8 km, T=450, 1 level): ~5.1k cells → ~2.3M potential rows; a few thousand ever materialize; single-digit MB. `dallas_full` (60×45 km, T=450, **3 levels**): ~216k cells → ~2.9×10⁸. `density_future` (60×30 km, T=1800, 1 level): ~144k cells → **~2.6×10⁸ potential rows** — enumeration is impossible; rows exist only as interned keys when a violation materializes them (the paper's 132k-row LP could afford full enumeration; ours cannot). The dominant memory at density scale is column **claim sets**, not rows: ~550 claims/column × ~26k flights × ~20 iterations ≈ 1.1 GB int32 — irrelevant at colgen_test scale, listed as a performance-PR item (store paths, recompute claims on demand).

### Pricing network (per flight)

- **States** `(cell q,r, level L, step t)` + origin ground states `(g, s)`. Cell domain: hex-ellipse corridor `{c : d(o,c)+d(c,d) ≤ d(o,d) + detour_slack_hops}` (config, default ~12) minus foreign `terminal_cells`, minus own terminal interior (entry/exit only via lane arcs). Step domain: `[base, base + max_ground_delay/dt + trip + slack]`. The `terminal_cells` subtraction is only a coarse prune; candidate acceptance still runs the exact wall check below.
- **Arcs** (v1, objective = delay-seconds per user decision 4): ground-hold `(g,s)→(g,s+1)` cost `dt` (chain rooted at `base = ceil(t_departure/dt)`, matching A*); takeoff per lane ℓ at the single level: `(g,s) → (ℓ.cell, L, s + takeoff_steps[L] + ℓ.steps)`, **cost = fold_leg_s(ℓ) = max(0, ℓ.dist − exit_radius(term, cfg)) / v** — the sub-hop leg `enroute_flown_m` keeps after folding to the column edge (`fold_corners_to_columns`), which varies per lane (0–4 s at terminal_radius 180) and is invisible to hop counts, so it must be priced or lane ranking is wrong (plan-critic round 2); claims = terminal dwell rows + lane-cell visit. Customer-origin takeoff: `(g,s) → (cell(P), L, s + takeoff_steps[L])`, **cost = ‖P − hex_center(cell(P))‖/v** (the hex-snap leg), claims = endpoint cylinder. Lateral hop `(c,L,t)→(c',L,t+1)` cost `dt`, claims = visit marks. Hub-arrival per lane / customer-arrival → SINK is permitted only after at least one lateral hop; it costs the same fold-leg/hex-snap term for the destination end and claims terminal rows + endpoint. A complete candidate is admitted only after exact static-wall certification and the A*-parity `max_detour_factor` check. Weight = ρ-contribution − Σ duals(claims); the per-flight constant `ref_time = enroute_reference_m/v` is added once at the sink so `delay_s = Σ hop·dt + fold legs + ground·dt − ref_time` ≥ 0 equals `metrics.total_delay_s` exactly (v1: air_hold = 0, single level ⇒ excess-altitude = 0 given the `_unimpeded_cruise_z` colgen branch = ladder floor). **When multi-level lands (§9), altitude enters the objective at both ends** (climb on takeoff, descent on arrival; matches `endpoint_altitude_change_m = (z0−ground) + (z1−ground) + interior_dz` and A*'s effective climb+descent pricing via `h_air`); at a single level those terms are per-flight constants and correctly drop out of argmin while still appearing in the *reported* `trajectory_cost`.
- **DP**: forward over t (DAG; longest path). Duals for visit windows via per-(c,L) prefix sums → O(1) per arc. Pure numpy first; numba kernel in PR C.

## 4. Architecture & integration

- `get_planner("colgen")` returns **`ColumnGenerationPlanner`** (user decision 5) with class attrs `plans_terminal_airspace = True` (passes `sim._wall_aware`) and `plans_whole_schedule = True`. Its per-flight `plan()` raises RuntimeError pointing at batch mode (colgen is whole-schedule by definition).
- **Relationship to A*'s network (user question, answered):** colgen and A* share the same lattice through the same *primitives* — `hexgrid` (cells, neighbors, `terminal_lanes`, `terminal_cells`, `circumradius`), config step math (`climb_steps_to`, lane steps), and the same reservation builder — which gives them identical endpoint/takeoff semantics and the same discrete center path. Colgen does **not** reuse A*'s edge-generation code (`astar._edges`): that code is entangled with per-step occupancy gating (which rows replace entirely), tie-breaking, and a byte-exact numba twin; extracting a shared enumerator would risk perturbing A*'s heavily-pinned byte-identical behavior for zero semantic gain. Parity tests require identical takeoff quantization and endpoint cylinders plus containment-equivalent, tag/clock-matched corridor geometry; a float-long lattice hop may deliberately appear as multiple contained builder sub-boxes rather than one byte-identical A* box.
- `sim.run` gets a **batch branch** next to the `parallel` branch: when the planner instance has `plans_whole_schedule`, call `colgen.run_batch(scenario, cfg, ledger, dss, static_terms, status, report, collector)` which solves once, then **files every flight through the normal `dss.commit`** in scenario order (so the mechanism's `any_conflict` re-check independently certifies the 0-denial property on every flight), then the unchanged `verify.find_interflight_conflict` backstop runs.
- Requires `terminal_airspace_always_active=True` whenever hub flights exist (v1 guard with a clear error; density family + colgen_test all set it). Non-hub scenarios (customer↔customer) run regardless of the flag. Lifting the guard is §9 item 4 — it needs one real extension, not a rethink.
- Requires `fixed_exit_lanes=True` whenever hub flights exist; the Phase-1 graph/claims encode those explicit boundary lanes. Customer↔customer flights are unaffected by this guard.
- Solver (user decision 9): a small backend seam in `master.py` — `GurobiBackend` (primary): one persistent `gurobipy.Model` across the whole column-generation run, columns added incrementally (`addVar(column=...)`), rows added incrementally on violation, duals from `Constr.Pi`, native MAXIMIZE (no sign gymnastics), LP warm-started from the previous basis, final IP via `var.Start = heuristic` + `MIPGap`/`TimeLimit`; `HighsBackend` (fallback, CI): `scipy.optimize.linprog(method="highs")` over a rebuilt `scipy.sparse` matrix + `scipy.optimize.milp` (no warm start — cold each round, fine at test scale). Backend chosen by guarded import, overridable via `ColGenParams.solver`. Determinism on BOTH backends: tie-breaks keyed (flight_id, lex state), rng = `np.random.default_rng(cfg.seed)`, single-threaded (`Threads=1` + fixed `Seed` for Gurobi).
- Metrics: `metrics._unimpeded_cruise_z` gets a `"colgen"` branch (ladder floor, same as astar). Intent fields populated like A*'s (`ground_delay_s`, `air_detour_m` via `enroute_detour_m`, `altitude_change_m` via `endpoint_altitude_change_m`, `cost = trajectory_cost(...)`); `solve_time_s` = per-flight translate+file time + amortized share of the solve wall time (documented).

- `class DualView` (ADD): row duals → per-(c,L) window prefix sums + terminal dual arrays; `visit_cost(c,L,j)`, `endpoint_cost(...)`, `dwell_cost(tid, s)` all O(1)/O(cells).
- `price_flight(fg, duals, pi_f, cfg, params) -> (reduced_cost, Column|None)` (ADD):
  ```
  labels[(c,t)] init −inf (single level v1); ground chain rooted at base (each hold step −dt), folded analytically per takeoff step s
  takeoff arc adds −fold_leg_s(lane or customer point) − terminal/endpoint dual sums     # delay units, see §3
  for t ascending: relax 6 neighbor hops; hop into c' at v adds weight −dt − Σ_{t'∈visit_rows(v)} λ(c',t')
      (per-VISIT dual attribution — the footprint rows depend only on v, not on entry/exit edges)
  state carries the last TWO cells — (c, prev, prev2, t) — forbidding hops into prev OR prev2 (round-3 MOD-1:
      prev alone blocks only Δ=2 backtracks; the lattice has 12 triangle classes per cell, and a Δ=3 triangle
      revisit shares row v+1, breaking pricing exactness). History depth = hi_off − lo_off from derive_cell_window
      (3 at defaults → ban Δ≤3 revisits; 1 at time_buffer_s=0 → no restriction needed), so it tracks config.
      Dominance retains max(2, history_depth) recent cells because destination-endpoint union/de-duplication can depend on
      the predecessor even when the revisit ban itself needs no predecessor.
  close via arrival arcs (−fold_leg_s − terminal/endpoint dual sums); +ref_time and benefit M at sink; rc = best − π_f
      (altitude terms return only with multi-level, §9 item 4 — constants at a single level)
  recompute rc from the DEDUPED claim set of the argmax path (exactness guard); return column iff rc > tol
  ```
  **Optimization sense (normative, one place):** the paper's MAXIMIZE Σ ρ_r x_r is the reference. The Gurobi backend maximizes natively (`ModelSense=MAXIMIZE`, duals from `Constr.Pi` used as-is); the HiGHS backend minimizes, so it passes `c = −ρ` and **negates `ineqlin.marginals`**. The pricing add-rule (`rc > 0`) and UB formula are stated and implemented in the maximize sense. All signs on both backends derive from this sentence.

## 9. Backlog (explicitly out of scope for v1; ordered, seams left open)

1. **Rolling horizon** (the stated next version): `ColGenSolver.solve` already takes an arbitrary request subset + a pre-populated ledger; the rolling driver re-solves every R seconds with committed flights frozen (their claims become fixed row loads).
2. **Return flights as tails / mission columns** (user: "eventually we will need to model return flights"): one column = outbound + turnaround arc + return, per the paper's tail machinery (Rule 5 connection arcs) — models delivery precedence (return cannot depart before the outbound's *planned* arrival, which independent legs cannot express). Requires splitting one mission column into two `OperationalIntent`s at translation. Scheduled after rolling horizon.
3. **Heterogeneous horizontal speeds** (user question, analyzed): cell rows survive unchanged (the sufficiency proof never uses unit transit); per-flight speed changes (a) pricing transit times τ per hop (paper's min/max-transit machinery), (b) claims computed from timed cell-intervals rounded outward, (c) filing — the builder times by global `nominal_speed_mps`, so per-flight speeds need centerline-timed building (the `decoupled` planner's `build_corridor` route). Moderate effort, no architectural change. **File as a repo issue when v1 lands.**
